# Redeemer Classification Framework

Purpose:
- classify redeemer organizations in a way that improves onboarding quality, predicts operational risk, and supports transparent policy decisions.
- provide a shared method for both internal governance and external communication.

Use cases:
- onboarding decisions (approve, conditional approve, defer)
- redemption-rate guidance by redeemer type
- risk anticipation and mitigation planning
- clear public explanation of why certain redeemers are strong protocol fits

---

## 1) Two-Layer Classification Model

Classify each redeemer with:
1. Function Type (what they provide)
2. Operational Profile (how they behave under load)

This separates mission fit from execution reliability.

---

## 2) Function Type Taxonomy

### A) Essential Access
Examples:
- transit
- utility-support programs
- childcare access

Governance significance:
- high public value, high sensitivity if fulfillment degrades.

### B) Public Culture and Learning
Examples:
- museums
- libraries
- public classes/workshops

Governance significance:
- strong inclusion value, often good off-peak capacity utilization.

### C) Health and Wellness
Examples:
- preventative care access programs
- community wellness services
- recreation centers

Governance significance:
- quality and verification standards may be stricter.

### D) Community Commerce Partners
Examples:
- local businesses with mission-aligned offerings

Governance significance:
- expands redemption utility, but requires careful consistency controls.

### E) MCE-Specific Event Partners
Examples:
- temporary offers tied to active MCE initiatives

Governance significance:
- high participation leverage, event-limited operational window.

---

## 3) Operational Profile Dimensions (Scored 1-5)

Score each redeemer on each dimension.

1. Capacity Elasticity
- Can the organization absorb redemption spikes without service collapse?

2. Marginal Cost per Redemption
- How expensive is each incremental redemption to fulfill?

3. Fulfillment Reliability
- How consistently are offerings honored as committed?

4. Service Criticality
- Is this offering essential, high-impact, or discretionary?

5. Verification Legibility
- How easily can a point-of-service confirmation be validated and audited?

6. Policy Discipline
- Willingness to follow epoch commitment rules, reporting norms, and committee guidance.

7. Participant Equity Access
- Accessibility across income, geography, schedule, language, and ability constraints.

8. Recovery Responsiveness
- Speed and quality of correction when performance issues occur.

---

## 4) Risk Tiering

Aggregate profile into tier outcomes.

### Tier G (Green): High-Fit / Low-Risk
- Strong reliability and policy discipline
- clear capacity model
- transparent verification flow

Policy default:
- standard onboarding, periodic review cadence.

### Tier Y (Yellow): Medium-Fit / Managed-Risk
- good mission fit but one or more operational weaknesses

Policy default:
- conditional onboarding with explicit remediation plan and tighter check-ins.

### Tier R (Red): High-Risk / Deferred
- repeated fulfillment failures, poor governance compliance, or unverifiable redemption flow

Policy default:
- defer onboarding or pause participation until controls are met.

---

## 5) Behavior Anticipation by Profile Pattern

If Capacity Elasticity is low and Service Criticality is high:
- expect saturation risk during participation growth.
- mitigation: quotas, narrower windows, staged expansion.

If Policy Discipline is low and Fulfillment Reliability is unstable:
- expect participant trust erosion.
- mitigation: conditional status, shorter commitment windows, stronger enforcement.

If Verification Legibility is weak:
- expect fraud/noise risk and disputes at redemption.
- mitigation: standardized POS confirmation steps, auditable redemption records.

If Marginal Cost is high but mission fit is strong:
- expect pressure for frequent rate changes.
- mitigation: planned calibration windows and explicit adjustment criteria.

---

## 6) Public-Facing Narrative Mapping

For each accepted redeemer class, communicate:
1. What value this redeemer type provides to participants
2. Why this type is a strong fit for civic credit redemption
3. How City/Sync ensures commitments are reliable
4. What guardrails exist if redemption demand changes

This keeps onboarding legitimacy understandable to non-technical audiences.

---

## 7) Pilot-to-Maturity Governance Path

### Pilot Phase
- City/Sync-led classification with committee observation.
- use initial scoring to build baseline performance history.

### Transitional Phase
- joint City/Sync + committee scoring, with published tier rationale.

### Maturity Phase
- committee-led classification with City/Sync standards oversight.
- cross-city comparability via shared taxonomy and scoring rubric.

---

## 8) Minimum Data Required per Redeemer Profile

- organization type and function category
- redemption offering mix
- monthly commitment capacity estimate
- historical fulfillment rate
- adjustment/change history
- participant complaint and resolution data
- average redemption confirmation quality
- equity access notes and constraints

---

## 9) Decision Outputs (Standardized)

Each classification review should output:
- function type label
- profile scorecard (1-5 by dimension)
- risk tier (G/Y/R)
- onboarding decision (approve/conditional/defer)
- required controls (if conditional)
- next review date

This creates consistent records, comparability over time, and transparent governance memory.
